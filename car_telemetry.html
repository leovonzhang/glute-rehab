1. 你要做成什么

一句话目标

做一个「车载黑匣子」：用 ESP32 把 IMU 体感 + GPS 记到 TF 卡，开完车把日志丢进本仓库的 Python 管道，自动出一份「驾驶体感 / 改装建议」报告。

MVP 不需要 PCB、不需要画板。杜邦线 + 面包板/洞洞板就够。分析管道已经写好，你可以现在就模拟跑通：

cd /workspace/car-telemetry
pip install -r requirements.txt
python3 run_pipeline.py --simulate
# 看 sample_report.md

固件可参考开源 jctoledo/blackbox（MIT）的思路与标定习惯；我们的传感器组合不同（BMI270 + M10+PPS + SD），所以别整仓硬烧，当参考即可。正式落盘格式以本仓库 SCHEMA.md 为准。

3. 工具软件安装（macOS / MacBook）

卡住了就把报错原文丢给贾维斯。下面每一步做完再进下一步。
3.1

二选一：Arduino IDE 或 PlatformIO

更新手走 A，更利落走 B

路线 A — Arduino IDE（推荐你先走这条）

  1. 打开 arduino.cc/en/software 下载 macOS 版，拖进「应用程序」。
  2. 打开 IDE → Settings / 偏好设置 → Additional boards manager URLs，加上：https://espressif.github.io/arduino-esp32/package_esp32_index.json
  3. Tools → Board → Boards Manager，搜 esp32，装 esp32 by Espressif Systems（装最新稳定版即可）。
  4. 板型选：ESP32S3 Dev Module。建议默认：USB CDC On Boot = Enabled，Flash 16MB，PSRAM OPI PSRAM（N16R8），Upload Speed 921600（不稳就改 460800）。
  5. 库管理器稍后装：Adafruit BMI270（或模块卖家示例用的库）、GPS 可用 TinyGPSPlus；SD 用自带 SD/SD_MMC。具体以后续固件仓库为准。

路线 B — PlatformIO（VS Code / Cursor）

  1. 装 VS Code 或继续用 Cursor。
  2. 扩展市场装 PlatformIO IDE。
  3. 新建项目：board 选 esp32-s3-devkitc-1，framework arduino 或 espidf。
  4. 串口监视在 PIO 终端里用 Monitor。
3.2

USB 驱动与端口

很多 S3 板 Mac 往往不用装 CH340
  • 很多 ESP32-S3-DevKitC 用板载 USB-JTAG/Serial，Mac 往往不用装 CH340。
  • 若卖家板子是 CH340 / CH343 转串口：用 Homebrew 装驱动，或按卖家说明装官方 macOS 驱动；装完重启一次。
  • 用数据线把板子插上 Mac，终端执行：
ls /dev/cu.*

常见会看到 /dev/cu.usbmodem* 或 /dev/cu.wchusbserial*。Arduino 里 Tools → Port 选这一项。

3.3

串口监视器

  • Arduino：Tools → Serial Monitor，波特率先试 115200。
  • 也可用：screen /dev/cu.usbmodemXXXX 115200（退出：Ctrl-A 再 K）。
  • 上传固件时若提示端口占用，先关掉监视器再点 Upload。

4. 接线总表

重要：下表引脚是 建议默认，以模块丝印与你到手的 DevKit 丝印为准。ESP32-S3 很多 GPIO 可重映射；接错电源（5V 进 3.3V 模块）会烧掉传感器——电源先对丝印，再接信号线。模块标 VCC/3V3 的接 3.3V；只有明确写 5V 的才接 5V。ESP32-S3 GPIO 是 3.3V 逻辑。
4.1

阶段策略（请按这个来）

第一步只接：IMU + GPS + 电源（+ USB 调试）。麦克风、TF 卡、按键 → 第二步再加。一次全接容易排错到崩溃。
4.2

ESP32 GND所有模块 GND必须共地，否则乱码/假数据

车内路试用 倍思车充 → USB-C → 开发板；不要从 OBD 口偷电给盒子（MVP 阶段）。

4.5

接线检查清单（通电前）

  1. 所有模块 共地。
  2. 没有把 5V 接到只标 3.3V 的脚。
  3. GPS 的 TX/RX 交叉（模块 TX→ESP RX）。
  4. 杜邦线插紧；面包板孔别松。
  5. 第一步：先不要插 TF 和麦克风，减少变量。

5. 第一次上电检查（冒烟 / 串口）

按这个顺序做

  1. 只插 ESP32（传感器先不接）→ USB 连 Mac → 选对端口 → 烧一个「Blink / Hello Serial」示例。
  2. 串口 115200 看到 Hello → USB 线、驱动、板型 OK。
  3. 断电，按 §4.3 接上 BMI270 + M10。再上电：板子不发烫、无焦糊味。若发烫 → 立刻拔 USB，查电源反接。
  4. 烧「只读 IMU」的最小草图（或后续给的 scan_i2c）：应扫到 BMI270 地址（常见 0x68/0x69）。
  5. 烧 GPS 透传：串口应刷 NMEA（$GNGGA / $GNRMC 一类）。天线朝窗，室内首次定位可能要几分钟。
  6. 有 PPS 时：示波器更好；没有的话固件里对 GPIO21 做中断计数，每秒大约 +1 即正常。
通过标准（第一步）：串口持续打印 IMU 三轴 + GPS 有 fix（或至少有 NMEA）→ 可以进入写卡与路试准备。

6. 最小固件：读 IMU + GPS，串口和 SD 写 CSV

分阶段，别一次写完美融合。
F0

串口证明活着

伪代码：

setup:
  Serial.begin(115200)
  Wire.begin(8, 9)          # SDA, SCL — 建议默认，以你板子为准
  imu.begin()
  gpsSerial.begin(9600, RX=17, TX=18)  # 建议默认

loop:
  读 accel/gyro → Serial.printf
  读一行 NMEA → Serial.print
  delay 适当（IMU 可 10ms 一帧做 100Hz 目标）
F1

符合 SCHEMA 的 CSV（先串口，再 SD）

目标文件（见 SCHEMA.md）：

imu.csv   t_utc, ax_g, ay_g, az_g, gx_dps, gy_dps, gz_dps, roll_deg, pitch_deg
gps.csv   t_utc, lat, lon, speed_kmh, fix, hdop
meta.json vehicle / annotations / firmware / mount_calib

伪代码：

setup:
  同上 + SD.begin(CS=10)     # 第二步接上 TF 后再开
  打开 /imu.csv /gps.csv 写表头
  若有 PPS: attachInterrupt(PPS_PIN, onPps, RISING)

onPps:
  记下 esp_timer 微秒，与下一包 UTC 秒绑定

loop @ 100Hz:
  采样 IMU，换成 g / dps，粗算 roll/pitch（可先静态公式）
  t_utc = 由 GPS+PPS 推出来的时间（没有 PPS 就用 GPS 时间 + 本地晶振外推）
  append imu.csv 一行
  若有新的 NAV-PVT / RMC: append gps.csv 一行
  同时 Serial 打一行心跳（方便你看着不像死机）
F2

参考 blackbox，但别整仓照搬

可借鉴不要照搬
停稳熄火再标定；重力定 z、直线加速定 xWT901 UART 驱动、ESP32-C3 引脚
驾驶模式阈值思路（加速/刹车/过弯）无 SD 的会话导出当主存储
u-blox UBX 配置思路NEO-6M 默认波特率假设

后续会给「对口 BMI270 + M10 + SD」的固件包；你现在用 F0/F1 验证硬件即可。

坐标系提醒（写进习惯）车体系：x 前、y 左、z 上；ax_g 加速为正、刹车为负；ay_g 左弯为正。装车方向尽量让模块箭头/丝印朝车头，后面标定会省很多事。

7. 车内安装与第一次路试

7.1

吸盘位置

  1. 斯迈林吸盘贴在挡风玻璃下方、尽量靠近车辆中线，不要挡视线、不要挡气囊区域。
  2. 盒子（开发板+模块）用扎带/3D 打印小壳固定在支架上——IMU 必须刚性，吸盘软晃会制造假振动。
  3. GPS 天线朝天、少被金属 A 柱挡住。
  4. USB-C 走线避开踩踏区，用车充供电；起步前线材整理好。
7.2

安全

  • 开车时不要低头看串口、不要调杜邦线。一切设置在停车熄火状态做完。
  • 第一趟选熟悉、车少的路，15–20 分钟即可。
  • 盒子松动就停车再固定，不要边开边摸。
7.3

隐私

  • 日志含轨迹与时间，当敏感数据：TF 卡、导出目录别随手上云公开仓库。
  • 语音（第二步麦克风）可能录到车内对话——默认本地存储，分享前先听/删。
  • 特斯拉 Fleet API 后续会涉及令牌与车辆位置，见 TESLA_FLEET_API.md 与 SECURITY_AND_AUTOMATION.md。
7.4

第一次路试步骤

  1. 停车、点火或仅 ON 挡，车上电，等 GPS fix（串口或 LED 约定）。
  2. 静止 10 秒（标定重力/零偏；习惯对齐 blackbox「停稳再 CLR」）。
  3. 正常开一段含：直线加速、轻轻刹车、一个弯。
  4. 回来拔 TF（先断电），在 Mac 上看是否有 imu.csv / gps.csv。
  5. 拷贝到 data/trip1/，手写一个简单 meta.json：
{
  "vehicle": {"type": "ice", "name": "Leo-ICE"},
  "annotations": [],
  "firmware": "mvp-f1",
  "mount_calib": {"note": "吸盘中线，第一次路试"}
}

特斯拉那趟把 type 改成 "tesla" 即可（OBD/API 文件可后补）。

9. 特斯拉 / 燃油车两条路

两辆车都要「体感盒子」

差别在车辆总线数据从哪来。

特斯拉燃油车（ICE）
体感盒子要（IMU+GPS+SD）要（同一套）
车速/油门等Tesla Fleet API / Telemetry（后续）vLinker MC+ 蓝牙 OBD
MVP 现在先只记盒子；API 配置见 TESLA_FLEET_API.md可先只记盒子；有 OBD 后再 obd.csv
管道同目录放 tesla.csv同目录放 obd.csv

特斯拉（后续，不必第一周做完）

  1. 按 TESLA_FLEET_API.md 申请/配置 Fleet API、Telemetry。
  2. 用 cartel.ingest 一类方法把遥测转成 tesla.csv。
  3. 与盒子日志一起 run_pipeline.py——管道会估计设备时钟偏移。

燃油车 OBD（有 vLinker 之后）

  1. 手机或电脑按说明书与 vLinker MC+ 配对（BLE / 经典蓝牙以设备为准）。
  2. 插入车辆 OBD-II 口（一般在方向盘下方）；点火。
  3. 原型阶段可用笔记本 + python-OBD 记 obd.csv（见 README）；ESP32 直连 BLE 是增强项，不是第一周必做。
  4. 采样目标：车速/油门/转速等约 2–5 Hz（受 ECU 限制）。

10. 常见坑与排错

先查什么

现象先查什么
串口无设备换能传数据的 USB-C 线；换口；CH340 板装驱动
上传失败 / 超时按住 BOOT 再按 RESET 进下载；降低 Upload Speed；关掉 Serial Monitor
I2C 扫不到 BMI270共地？SDA/SCL 对调试一下；地址 0x68/0x69；供电是否 3.3V
GPS 一直无 fix天线朝窗/户外；供电；TX/RX 是否交叉；波特率是否仍是 9600
NMEA 乱码波特率不对；地线虚接；USB 与模块同时供电造成回流问题（共地）
SD 初始化失败卡是否 FAT32；CS 脚；有的模块要 5V；杜邦太长信号差就减短
车里一颠数据疯抖吸盘软、盒子晃 → 加强刚性固定
报告特征离谱安装方向反了；未做静止标定；CSV 单位不是 g/dps
Mac 读卡慢/不认用正经读卡器；先安全弹出再拔
买错板主控必须 N16R8；M10 必须问清 PPS
排错口诀：一次只改一样（线、库、波特率、供电），改完记笔记。

一句话收尾

先买对 N16R8 和带 PPS 的 M10 → 桌上串口看到 IMU+GPS → 再写卡上路 → 把目录丢给 run_pipeline.py。PCB 和完美融合都是以后的事。

有问题把照片 + 串口原文丢过来就行。

安全提示

  • 开车时不要低头看串口、不要调杜邦线；一切设置在停车熄火状态做完。
  • 接错电源（5V 进 3.3V 模块）会烧掉传感器；发烫立即拔 USB。
  • 日志含轨迹与时间，当敏感数据，不要随手上云公开仓库。
